## 范围与测量口径

2026-11-04 对当前结构预览进行资源核对，并在统一 npm run verify 通过后复测正式 dist。数字分别表示原始文件字节和标注的本地压缩估算，未安装依赖、替换框架或调整托管资源。没有用发布目录大小代替浏览器加载量，也未据此声称 LCP、INP 或 CLS 得到改善。

基线来自修改前的现有 dist，共 **40 个正式文件、1,256,696 B**；第二次统一验证后的最终构建为 **30 个正式文件、1,022,642 B**，原始发布体积净减 **234,054 B（18.62%）**。临时浏览器验收页面 deep-review、storefront-review-v2 的 HTML/CSS 均不属于正式构建，前后测量都已排除。最终测量使用已知的 30 个正式文件清单，避免同时进行的页面验收污染计数。

逐文件哈希、全部 13 条页面路由的依赖、图片声明和压缩估算已分别保存至本次工作区的 japan-life-performance-baseline.json、japan-life-performance-final.json。对比结果如下。

## 本次构建修改

原构建会把整个 public 目录复制到 dist。现在先在内存中渲染全部 13 个静态页面，验证依赖后再创建发布目录，只复制可达的资源。public 中的原始文件全部保留。

依赖检查覆盖当前站点使用的 HTML/SVG 本地 href、src、poster、普通 srcset，CSS 的 url() 与 @import，以及 JavaScript 的静态 import、export-from 和使用普通字符串的 import()。检查沿引用递归进行，因此样式引用的图片、字体以及模块引用的其他模块都会进入发布目录。

_headers 和 robots.txt 显式保留；存在 _redirects 时也会保留。搜索、购物袋和后台通过商品数据动态生成图片路径，因此商品目录中的 image 字段另外作为资源入口，不依赖静态页面恰好展示全部商品。后台按页面单独加载的 admin.js 由 HTML 引用自然纳入。若实际使用字体，会同时保留同目录的 OFL、LICENSE、COPYING 许可文件。

本次正式构建排除以下 **11 个未引用文件、255,301 B**，约为原发布目录的 **20.3%**：

| 未引用资源 | 原始大小 |
| --- | ---: |
| 旧 refinement.css | 19,550 B |
| 旧宋体字形子集及许可 | 126,510 B |
| 旧 hero-editorial.webp | 87,930 B |
| 七个旧 SVG 插画 | 21,311 B |
| 合计 | **255,301 B** |

这些文件在现有页面中已经没有加载入口。因此收益是减少发布文件和上传体积、避免过期素材继续发布，**不构成首页网络加载减少 255,301 B**。本轮其余代码、页面及后台独立脚本合计净增 21,247 B，所以最终发布目录的净减少量为 234,054 B。

## 页面加载与维护收益

前台原来加载包含后台模块的 app.js。后台改为独立 admin.js 后，前台不再下载、解析后台视图代码。最终 admin.js 为 8,658 B，gzip 估算 3,783 B；它只在后台加载。后台页面的声明资源原始大小减少 23,388 B，gzip 估算减少 7,625 B（24.25%），这是本轮明确的按页面加载收益。

但前台也增加了交互处理：最终 app.js 从 27,194 B 增至 29,980 B，store-core.mjs 从 3,700 B 增至 3,958 B，chapter.js 保持 4,487 B。首页实际使用的前台 JavaScript 合计净增 3,044 B，gzip 估算净增 380 B。后台拆分减少了职责混杂，不能据此宣称这一轮前台脚本净变小。

旧首页 CSS 选择器清理使 styles.css 从 39,471 B 减至 33,023 B；界面细节规则使 edition.css 从 38,341 B 增至 43,847 B。最终两份 CSS 合计减少 942 B，gzip 估算减少 254 B，未扩大为全站 CSS 重写。

前台内嵌数据去除了未使用的字段，以首页为例从 4,912 B 减至 4,385 B，减少 527 B。其他 HTML 增加了界面内容和语义属性，因此应看最终 HTML 合计；全部 13 页原始 HTML 从 266,043 B 增至 276,530 B，逐页 gzip 估算之和从 67,860 B 降至 67,709 B。

## 维护约定与验证

- 新增本地资源应由页面、CSS 或模块中的字面量路径引用；商品图片继续登记在 catalog 的 image 字段。
- 这个无依赖扫描器服务当前项目，不是通用打包器。若以后引入计算得到的模块路径、其他运行时生成资源、内联模块或新的资源格式，需要在构建入口显式登记或扩展针对性的引用规则。普通字符串 import() 已覆盖；模板插值、计算表达式不自动推断。
- 本地依赖缺失会使构建报错，检查发生在清空旧 dist 之前。没有引用的 public 源文件不被删除。
- npm run check 同时核对 HTML/CSS/ESM/SVG 的本地依赖，继续检查 noindex、托管文件及交易/管理未配置保护。
- 构建脚本已通过 Node 语法检查，内存计划核对了 CSS 引用、静态及动态模块引用、首页路径和缺失资源报错。统一 npm run verify 已通过：13 个页面、17 个依赖文件、551 处本地链接或资源、19 项测试。
- 最终复测只读取正式 dist，没有重新构建或写入发布目录。每条页面路由的 HTML、CSS、模块、声明的非 lazy 图片和压缩估算分别记录；浏览器功能验收独立进行，本记录不包含实际网络瀑布或网页性能分数。

本轮仍然是结构预览；资源优化没有启用支付、真实订单、管理身份或费用预警。
