## 本轮确认并修复的问题

### 1. 购物袋删除撤销后的焦点落到隐藏链接

修前，移除唯一的米白毛巾、撤销并关闭操作提示后，焦点可能落到 `aria-hidden=true` 的商品图片链接。修后只选择可见、未禁用、非 inert 的控件；相同操作后焦点返回可见的“柔软日用毛巾”名称链接。空列表会回到可见的浏览入口。

### 2. 多个页面和存储失败时覆盖较新的本机状态

购物袋与收藏现在分别维护最后可读基线、待保存操作和当前值。每次写入前重新读取已有数据，再将本页明确的加入、取消、增减或恢复动作合入；写入失败时保留本页操作；读取恢复后重放本页动作，并在下一次本页操作时尝试保存。读取失败时不尝试用旧快照覆盖存储。购物袋保存成功不会清除收藏仍未保存的状态。

实际复验：另一同源页面把数量 2 改为 3，当前数量输入框仍保持焦点；当前输入框尚未提交的“9”在另一页面把已保存数量 3 改为 4 后仍保留，已保存基线与金额按 4 件更新。随后通过界面恢复原值。

这降低了读取旧快照、延迟收到同步事件和存储失败造成的覆盖风险。localStorage 不提供跨上下文原子事务，不能保证两个页面在完全同时读写时绝对无竞争；真实订单不能依赖这套本机逻辑。

### 3. 公开商品接口可能带出草稿规格图片

封面、替代文字和详情图片列表改用一致条件：允许商品级图片，以及属于同一商品且状态 active 的规格图片；排除草稿、归档和关联不符的规格图片。新增真实内存 SQLite 测试覆盖共享图片、活跃规格兜底、只有隐藏规格图片时返回空结果等情况。

### 4. API 路由与索引约束不一致

开发服务器与 Wrangler 配置都覆盖 `/api` 和 `/api/*`，未知 API 返回 JSON 404；`/apiary` 仍按静态路径处理。全部 JSON API 响应增加 `X-Robots-Tag: noindex, nofollow`。本地环境密钥文件的忽略模式改为 `.dev.vars*`，覆盖环境后缀。

独立开发服务检查：GET `/api`、HEAD `/api`、GET `/api/` 均为 JSON 404，HEAD 无正文；`/api/health` 为 JSON 200；`/apiary` 和 `/apiary/health` 为静态 HTML 404。远程路由和响应头尚未实测。

### 5. 后台辅助文字偏淡、手机说明偏小

表头、准备项、商品标识和侧栏底部链接统一使用现有 `--muted`；空态标题使用 `--ink`。普通文字对白底的计算对比度为约 5.40:1，表头文字对现有背景约 5.03:1，空态标题对白底约 17.81:1。手机指标和准备状态说明调整为 11px，并检查实际内容未被挤出卡片。这里只核对了这些具体配色和显示状态，不等同于完整 WCAG 合规认证。

### 6. 320px 窄屏的文案覆盖与孤字换行

- 收紧静物文案块的内边距、位置和字号；托特包左侧包带更完整，茶饮与洗护也复查了同一规则。
- 首页分类入口将“浏览”与分类名称分成不可拆的短语，“茶与食”不再只留下一个“食”字在末行。
- 搜索结果的“演示价”和“选品示意”分别按完整文本组换行；320×500 视口内没有单字尾行。
- 404 按钮文案统一为“浏览全部选物”。

## 关键交互复验结果

- 米白毛巾 2 件与浅灰毛巾 2 件分为两行，总计 7,200 JPY。移除浅灰后恢复为米白 2 件、3,600 JPY。
- 数量为 1 时输入 3 并立即点击减少，得到 2 件、3,600 JPY；本轮没有复现这条路径的数量错误，未将它列为修复项。
- 在收藏列表聚焦最后一个收藏按钮，另一同源页面取消该收藏后，列表变空，焦点移到可见的“浏览全部选物”入口。
- 商品表格在 320px 容器下可视宽约 267px，内容约 520px；ArrowRight 后 scrollLeft 增加，页面本身没有随表格横向撑开。
- 320×500 分类菜单位于视口约 18–482px；内部可滚动到最后的购物说明入口。搜索、菜单和大图的关闭与回焦均按实际界面操作检查。
- 最后保留原有米白毛巾 2 件、总计 3,600 JPY、无收藏状态；没有清空浏览器其他数据。
